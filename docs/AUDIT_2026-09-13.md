# VIGIL product, design, and implementation audit

Date: 2026-09-13

Audited revision: `77f7ba6` (`feat: implement core VIGIL application`)

Decision: **not ready to share as a trusted MVP yet**

## Executive assessment

The repository contains a substantial native Android implementation, not a static mockup. Its strongest foundations are the local Room model, timestamp-derived live timer, light/dark tokens, correction primitives, and a clear product loop: act now, understand the day, prepare tomorrow.

The current build nevertheless misses several approved promises. The largest risks are not cosmetic:

- first-run onboarding is marked complete before the user completes it;
- backup/restore is incomplete and can commit a partial failed import;
- future database migrations are configured to erase data;
- the app promises device-only data while Android backup is enabled;
- reminder timing controls do not schedule anything, and the idle reminder does not exist;
- several actions silently discard failures while the interface closes as if they succeeded;
- review metrics can be mathematically misleading;
- the claimed build/test evidence in `docs/BUILD_STATUS.md` cannot be reproduced from this checkout.

The implementation also falls short of the requested premium cinematic product. It has useful colors and a timer halo, but the Today screen does not use the landscape centerpiece, Timeline and Review are mostly uniform card lists, the motion language is shallow, and accessibility preferences are not wired through the experience.

## What was inspected

- All Kotlin source under `app/src/main/java`.
- Room entities, DAOs, state transitions, day/review derivations, import/export, and reset behavior.
- Onboarding, Today, Focus Timer, Timeline, Review, Settings, activity, gap, and priority interfaces.
- Manifest, Gradle configuration, resources, tests, metadata, repository contents, and Git state.
- The three original mockup boards in the repository.
- The seven supplied app-quality, onboarding, retention, gamification, and UX transcript files. They were treated as advisory source material, not as instructions or proof.

## Evidence boundary

This was a source and contract audit. Native execution is still **unverified** because this checkout has no Gradle wrapper, and the current machine exposes no usable JDK, Gradle installation, or Android SDK. No APK, emulator, physical-device run, Compose screenshot set, TalkBack pass, or notification delivery trace was present. Source review can identify defects; it cannot prove that the application compiles or looks correct on a phone.

Severity: **P0** release blocker or credible data-loss/privacy risk; **P1** broken core behavior; **P2** meaningful journey/accessibility/design/product-quality defect; **P3** polish or maintainability debt.

## P0 — release blockers

### VIG-A01 — Onboarding is automatically bypassed

`VigilRepository.initializeDefaultsIfNeeded()` creates settings with `hasCompletedOnboarding = true` (`VigilRepository.kt:137-142`), and both view models invoke the initializer. `MainActivity` only shows onboarding while that flag is false (`MainActivity.kt:60-68`). On a new installation the welcome screen can flash and disappear or be skipped entirely.

Fix: initialize settings with onboarding incomplete, make catalog creation independent of onboarding completion, and add a first-launch integration test.

### VIG-A02 — Restore is incomplete and a failed import can commit partial writes

- Export loads settings and wake markers but never serializes them (`VigilRepository.kt:809-888`).
- Priorities are exported but not imported (`VigilRepository.kt:876-990`).
- Import writes records while parsing, then catches errors inside `withTransaction` and returns `Result.failure` (`VigilRepository.kt:891-990`). Because no exception escapes, Room can commit earlier writes.
- Import merges with existing records via `REPLACE`; it does not validate and atomically replace the database as claimed.
- References, overlaps, open intervals, and multiple live sessions are not validated.

Impact: a backup does not preserve the full app, and malformed input can leave a mixed/corrupted database while reporting failure.

Fix: parse and validate a bounded backup before the write transaction; preview counts; replace all supported records in one transaction. Include settings, priorities, wake markers, IDs, revisions, timezone metadata, and every supported field. Failure must preserve the previous logical database exactly.

### VIG-A03 — Future schema changes are configured to erase history

`AppDatabase.kt:55` calls `fallbackToDestructiveMigration()` and `exportSchema` is false at line 33. A future database version without a migration can delete the history VIGIL exists to preserve.

Fix: remove destructive fallback, export Room schemas, commit explicit migrations, and test a populated migration fixture.

### VIG-A04 — The privacy promise conflicts with Android backup

Onboarding says all data stays on this device (`OnboardingScreen.kt:92-126`), while the manifest declares `android:allowBackup="true"` (`AndroidManifest.xml:6-12`). Depending on device policy, data may participate in system backup outside VIGIL's manual export.

Fix: for the current strict local-only policy, disable platform backup and define extraction rules. If platform backup is retained later, rewrite the promise accurately.

### VIG-A05 — The release is not reproducible from the repository

There is no Gradle wrapper, README, `.gitignore`, or `app/proguard-rules.pro`. `.gradle` caches and an empty `.env` are tracked. This host lacks a usable Android toolchain, so previous build claims could not be reproduced. Existing tests do not exercise the repository or Android app.

Fix: commit a standard wrapper, prerequisites/run instructions, ignore rules, release rules file, and clean CI/build path. Record APK checksum, variant, revision, and device installation before sharing.

## P1 — core behavior defects

### VIG-A06 — Reminder settings do not implement delayed or idle reminders

Pausing calls `showPauseReminder` immediately (`VigilViewModel.kt:190-198`; `FocusTimerViewModel.kt:260-267`). `pauseReminderMinutes` and `idleReminderMinutes` are never used for scheduling. `NOTIFICATION_ID_IDLE` is declared but no idle notification exists. There is no scheduler/receiver/service or persisted scheduling record. `POST_NOTIFICATIONS` is declared without a runtime permission flow. Settings reports a successful test trigger regardless of delivery (`SettingsScreen.kt:247-250`).

Fix: implement one-shot OS work with stable identifiers, persisted reconciliation, permission state, quiet hours, sleep suppression, snooze, rate caps, and current-state routing. Tracking must remain usable if permission is denied.

### VIG-A07 — An invalid switch can finish the current session

`switchSession()` closes the current interval/session before validating the new activity (`VigilRepository.kt:302-315`). Returning `Result.failure` does not roll the transaction back.

Fix: validate destination and all preconditions first, then atomically finish/start. Add rollback and rapid-repeat tests.

### VIG-A08 — Open-interval lookup can target the wrong record

`getOpenInterval()` selects any row where `endInstant IS NULL LIMIT 1`, without session ID or deterministic order (`Daos.kt:104-105`). Transitions then close that global row.

Fix: query by current session ID and expected kind; enforce one live/open record where practical; detect and repair invalid states explicitly.

### VIG-A09 — Generic history editing can corrupt a live session

Every timeline interval, including an open active/pause interval, opens the generic editor and can be deleted (`TimelineScreen.kt:317-325`, `453-467`). Repository edit/delete does not reconcile the owning live session.

Fix: live records change only through session commands. Completed-session correction validates and updates the full segment set atomically.

### VIG-A10 — Review values can be wrong or semantically mislabeled

- Each active/manual interval increments `sessionCount`, so one paused session becomes multiple sessions (`VigilRepository.kt:503-520`).
- Sleep is added to `totalRecorded` but not the average divisor.
- Manual entries can become “longest uninterrupted focus” regardless of activity.
- `totalUntrackedMs` is always zero (`VigilRepository.kt:551-560`).
- `daysWithDataCount` is forced to at least one.
- Overlapping intervals are summed independently and can exceed elapsed time.
- Review labels these values “Average Session” and “Uninterrupted focus” (`ReviewScreen.kt:151-188`).

Fix: derive metrics from normalized disjoint spans; count unique completed sessions; define manual-entry eligibility; sum per-day untracked windows; return zero days for no data; label exactly what is calculated.

### VIG-A11 — Sleep can overlap history and double-count the day

`recordSleepInterval()` checks only end-after-start and inserts directly (`VigilRepository.kt:716-729`). Day totals sum overlaps independently (`VigilRepository.kt:410-470`).

Fix: route sleep through the same collision/preview rules as manual entries, with an explicit replace/split decision.

### VIG-A12 — Today’s priority editor writes to tomorrow

The card is labeled “Today's Intentions,” but its save callback calls `setTomorrowPriorities` (`TodayScreen.kt:492-503`).

Fix: call `setTodayPriorities` and add a local-date persistence test.

### VIG-A13 — Mutation failures are mostly invisible

View-model actions discard repository results for timer transitions, switching, manual entry, edit, sleep, and creation. Dialogs close immediately. `snackbarMessage` is never assigned a failure or undo message.

Fix: expose loading/success/error outcomes; close surfaces only on success; preserve input on failure; offer retry; deduplicate rapid commands.

### VIG-A14 — Archived and invalid activities can remain selectable

`VigilViewModel` observes all activities (`VigilViewModel.kt:117-121`), and `activeActivities`/`allActivities` alias the same list (`VigilViewModel.kt:463-467`). Starts and edits do not consistently validate archive status or category existence.

Fix: distinct active/all streams, reject archived starts, validate references, and add real rename/archive/restore management.

### VIG-A15 — Midnight and wake-aware behavior becomes stale or misleading

Greeting/date are remembered without clock refresh (`TodayScreen.kt:117-131`). Priority and wake flows capture one date at initialization (`VigilViewModel.kt:127-144`). Wake is returned but does not affect gap baseline; today's untracked time starts at midnight (`VigilRepository.kt:389-480`). Future dates become a full “untracked” day.

Fix: centralize a testable day clock, roll subscriptions at midnight/timezone change, separate pre-wake/sleep/awake-untracked semantics, and label future time separately.

## P2 — product, interaction, and design defects

### VIG-A16 — The primary action is split into two timer products

Today presents Daily Tracker and Focus Timer as separate modes backed by two view models. Both control the same live session but carry different local behavior. A normal untargeted session can acquire an implied focus target when viewed in Focus mode; selecting/switching also differs.

Direction: one prominent **Now** tracker handles every activity. Optional duration/intention expands that same session into a focus session.

### VIG-A17 — Focus preferences and intention are not durable

Timer display mode, intention, completion-notification toggle, and focus haptic toggle live only in `FocusTimerViewModel`. They are not stored in settings/session records; the haptic option has no effect. Process restart can change display and lose intention.

### VIG-A18 — Reduced motion and haptic preferences are cosmetic

`TimerHalo` and `MountainLandscape` accept reduced motion, but callers do not pass the saved setting. Bottom navigation always haptics; `settings.hapticsEnabled` is not consulted. Focus haptic has no implementation.

### VIG-A19 — Forced app theme can disagree with component art

The app respects saved theme, but Today, Focus Timer, and Mountain Landscape call `isSystemInDarkTheme()` directly. Forcing a theme can render mismatched inner surfaces. The XML launch theme is always light, risking a bright dark-mode startup flash.

### VIG-A20 — Historical-entry defaults and failure flow are poor

Timeline passes midnight to `ManualEntryDialog`, which derives 23:00 and 00:00 on one date—an invalid default. Cross-midnight entries are impossible, raw `HH:mm` fields ignore time-format preference, and repository rejection arrives after the dialog closes.

### VIG-A21 — The visual result has not met the supplied quality bar

Source comparison to the boards:

- the cinematic landscape appears only in onboarding, not Today’s signature timer;
- Today’s hero is a generic radial surface rather than an atmospheric scene;
- Timeline lacks the strong time rail and calibrated density of the references;
- Review lacks a clear balance visualization, horizon moment, trend shape, and closing ritual;
- repeated bordered cards flatten hierarchy;
- motion is mostly crossfade/color/halo breath, without start/pause/finish choreography;
- copy such as “No arbitrary scores or fake trends” is defensive product language rather than calm guidance.

Final visual severity remains unverified until the app is rendered on target Android sizes in both themes.

### VIG-A22 — Accessibility coverage is not evidenced

Many compact chips/clickable boxes lack semantic role/state and may be smaller than 48dp. Charts have no grouped accessible summary. There is no instrumentation suite, TalkBack trace, large-font evidence, focus-return check, or contrast report.

## P3 — maintainability and repository debt

- `TodayScreen.kt`, `FocusTimerComponent.kt`, and `VigilRepository.kt` are very large and mix presentation, derivation, and orchestration.
- Navigation/settings state is duplicated between `MainActivity` and `VigilViewModel`.
- `metadata.json` advertises a server-side Gemini capability although VIGIL is local-only.
- Build status names a `vigil_reminders` channel while source uses `vigil_checkins`.
- Tests mostly reimplement arithmetic instead of invoking production behavior; they can pass while the repository is broken.

## Strengths to preserve

- One honest purpose: understand where time went and gently return to intention.
- Local-first, no-account starting point.
- Timestamp-derived elapsed time rather than per-second database writes.
- Explicit active, pause, manual, sleep, wake, and priority records.
- Light/dark palettes with coherent mint/amber vocabulary.
- Gap labeling/correction as first-class behavior.
- Pauses treated as information rather than moral failure.
- The mountain/light motif and dominant timer in the supplied references.

## Release recommendation

Do not connect real accounts or expose shared personal statistics before repairing P0/P1 issues and proving server authorization. Friends/Close Friends, selective sharing, and fair opt-in challenges are nevertheless part of the current serious-alpha program after that trust foundation, not an indefinite later feature. Calendar sync, passive app surveillance, and Wear OS remain separate. The superseding order and gates are in `docs/IMPLEMENTATION_AND_AUDIT_PLAN_2026-09-13.md`.
